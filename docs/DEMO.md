# LumiTwin 시연 대본

면접에서 화면을 띄워 보여 주거나 시연 영상을 찍을 때 쓰는 대본입니다. **3분 기본판(실행 MES)**, **시연 영상 녹화**, **더 보여 줄 때**, **2분 짧은판**, **예상 질문**, **문제가 생겼을 때**로 나눴습니다.
"말할 것"은 그대로 읽어도 되게 썼고, "할 것"은 그때 누를 곳입니다. 버튼 글자는 화면에 보이는 그대로 적었습니다.

> 가상 공장입니다. 공개 자료와 가정값으로 만들었고, SL의 실제 라인·수치·데이터를 쓰지 않았습니다. SL과 무관한 개인 프로젝트입니다.

## 준비 (시작 10분 전)

| 할 일 | 방법 |
|---|---|
| 앱 띄우기 | 처음이면 `npm run build`. 그다음 `npm run start`(운영 모드). 공개 링크까지 필요하면 `npm run share`. `http://localhost:5180`을 열고 상단 오른쪽 MES·엣지 점이 초록색인지 본다 |
| 새 실행 | 준비용으로 **라인 조장**이나 **시스템 관리자**로 로그인한다(상단 `로그인` → 계정 버튼). 상단 `초기화`로 새 실행을 시작하고 `60×`로 올린다 |
| 시나리오 | 상단 `이상 시나리오`에서 **웜기어 세트 불량 LOT 입고**를 켠다. 녹화·시연 시작 **약 2분 전**에 **칩 마운터 헤드 베어링 마모**를 켠다(아래 표). 배속은 `60×` 그대로 둔다 |
| 로그아웃 | 준비가 끝나면 사용자 메뉴 → `로그아웃`. 시연은 로그인부터 시작한다 |
| AI 비서 모드 | 비서 창 위쪽에 `Claude` 또는 `모의 모드`가 보인다. 키가 없으면 모의 모드로 해도 흐름은 같다 |
| 공개 링크로 할 때 | 공개 링크는 보기 전용이라 로그인 버튼이 없다. 상단 `보기 전용`을 눌러 제어 키(`server/.env`의 `CONTROL_KEY`)를 넣어 `조작 가능`으로 바꾼 뒤 로그인한다 |
| 창 | 브라우저 창 하나, 확대 100%, 너비 1536px 이상(그래야 상단에 `AI 비서`·사용자 이름·`OPC UA` 글자가 다 보인다) |

**시연 계정** (로그인 화면의 계정 버튼. 기본은 버튼만 누르면 들어간다)

| 계정 | 이름 | 이 대본에서 쓰는 곳 |
|---|---|---|
| `lead1` | 라인 조장 | 작업지시, MRB 판정, Hold 걸기 |
| `mt1` | 보전 담당 | 보전 실시 |
| `qa1` | 품질 담당 | (더 보여 줄 때) Hold 해제, 변경점 승인 |
| `op1` | 현장 작업자 | (더 보여 줄 때) 작업자 태블릿 |
| `admin` | 시스템 관리자 | (더 보여 줄 때) 감사 기록 |

서버에 `DEMO_PASSWORD`를 정했으면 계정 버튼은 아이디만 채운다. 그때는 비밀번호를 입력하고 `로그인`을 누른다.

**시나리오가 증상을 내기까지 걸리는 시간** (시뮬레이터로 잰 값. 실제 시간 = 가상 시간 ÷ 배속)

| 시나리오 | 잰 결과 | 가상 시간 | 20배속 | 60배속 |
|---|---|---|---|---|
| 웜기어 세트 불량 LOT 입고 | 켜고 1.5시간 뒤 사이드미러 기능 검사 불량률 23.6% (소음 25건·모터 전류 4건, P4 때 잰 값) | 1.5시간 | 4분 30초 | 1분 30초 |
| 칩 마운터 헤드 베어링 마모 | EM-MT-B1 진동이 B/C 경계를 넘어 `경고 (보전 계획)`, 그 뒤 마모가 0.8을 넘으면 고장 위험이 커진다 (씨앗 3개로 잰 값) | 경고 2~3.5시간, 고장 위험 4~6시간부터 | — | 경고 약 2~4분, 고장 위험 약 5~6분부터 |
| 증착 챔버 미세 누설 | 켜고 약 50분 뒤 펌프다운 시간이 관리 상한(14분)을 넘고, 그 무렵 백화 불량률 상승 알람이 뜸 | 약 50분 | 약 2분 30초 | 약 50초 |

- 시나리오는 끌 때까지 효과가 남는다. 웜기어 LOT는 끄는 순간 그 LOT를 격리한다. 시연이 끝나면 꺼 둔다.
- 베어링 마모는 처음 마모가 실행마다 달라(0~0.3) 시간이 흔들린다. 시연 때 아직 경고가 없으면 다른 장면을 먼저 보여 주고 돌아온다. 고장이 먼저 나 버리면 고장 수리 완료 → 마모가 0.1로 돌아간다는 설명으로 바꾼다.

- `/orders`에서 기종 변경을 빨리 보여 주려면 진행 중 작업지시를 `중단`한다. 라인이 다음 작업지시(방금 올린 것)를 받는다. 이미 투입한 것은 그대로 흐른다.

## 시연 영상 녹화

1. **화면**: 1920×1080 모니터에서 브라우저를 최대화하고 확대 100%로 둔다. 북마크바·다른 탭·바탕 화면 알림(방해 금지)을 끈다. 녹화는 1920×1080, 초당 30프레임이면 충분하다.
2. **녹화 도구**: Windows 11 캡처 도구의 화면 녹화나 OBS Studio 같은 것을 쓴다. 마이크로 말을 함께 넣거나, 소리 없이 찍고 자막을 붙인다.
3. **미리 켜 둘 것**: 위 **준비** 표를 그대로 한다. 앱은 `npm run start`(운영 모드)로 띄운다(개발 모드는 화면을 처음 열 때 느리다). 녹화할 화면(`/orders`, `/ncr`, `/trace`, `/changes`, `/maintenance`, `/reports`)을 한 번씩 미리 열어 둔다. 웜기어 LOT는 녹화 2분 이상 전에, 베어링 마모는 약 2분 전에 켠다. 배속은 `60×`.
4. **찍기**: 로그아웃한 3D 공장 화면에서 녹화를 시작하고 3분 기본판 순서대로 간다. 마우스는 천천히 움직이고, 누를 곳에서 1초 멈춘다.
5. **다듬기**: 3분이 넘으면 화면 전환 사이를 자른다. 처음 2초에 제목(프로젝트 이름·"가상 공장, 실제 데이터 아님")을 넣는다.
6. **올리기**: 영상을 어디에 올릴지(예: 일부 공개 영상)와 README에 링크를 다는 것은 직접 정한다.

## 예상 질문

**왜 가상 데이터인가요?**
실제 공장 데이터는 대외비라 쓸 수 없습니다. 대신 공정 순서·파라미터를 공개 자료로 조사하고, 근거 등급(확인·약함·가정)을 모든 값에 달았습니다. 불량 인과도 "원인 공정과 증상 공정이 다르다"는 현장 특성을 넣어, 데이터를 따라가야 원인이 보이게 만들었습니다.

**인터록은 어떻게 판정하나요? DB가 느리면 라인이 서지 않나요?**
게이트 설비가 투입 순간 MES에 묻고, MES는 Hold → 불량 미처리 → 재검사 순서 → 공정 순서 → 작업지시 → 초물 순서로 처음 걸리는 것을 답합니다. DB를 읽지 않고 메모리에 둔 개체 상태로 바로 답합니다. 메모리는 서버가 뜰 때 DB 기록에서 되살리고, 되살리기 전에는 '기다림'으로 답합니다.

**MES가 죽으면요?**
설비는 사이클 끝 + 3초까지 답이 없으면 확인 없이 통과시키고, 그 개체에 '무응답 통과' 표시를 남깁니다. MES 하나 때문에 라인 전체를 세우지 않는 선택이고, 나중에 그 개체만 골라 다시 확인할 수 있습니다. 3번 연달아 답이 없으면 MES가 멈춘 것으로 보고 기다리지 않습니다. 이 기준은 가정값입니다.

**MRB는 무엇이고 왜 두었나요?**
처리 기준으로 정할 수 없는 불량을 품질·생산 담당이 모여 수리·재작업·폐기·특채 중 하나로 정하는 절차입니다. 여기서는 광도 미달, 코팅 기포, 작동 소음처럼 규격 근처에서 재측정 편차일 수 있는 불량에만 두었습니다. 나머지는 MES가 기준대로 자동으로 정합니다. 특채는 근거 메모 없이 내릴 수 없습니다.

**4M 변경점은 어떻게 잡나요?**
교대(사람), 고장 수리·보전(설비), 자재 LOT 교체(자재), 기종 변경(방법)은 시뮬레이터가 자동으로 알리고, 사람이 신고할 수도 있습니다. 초물이 필요한 변경이면 그 설비의 첫 개체를 초물로 검사하고, 합격하기 전에는 인터록이 다음 투입을 기다리게 합니다.

**남은 수명 추정은 믿을 만한가요?**
진동 추세를 경계까지 직선으로 늘린 단순 추정입니다. 마모는 끝으로 갈수록 빨라지는데 직선으로 늘리므로 끝 무렵에는 실제보다 길게 잡습니다. 표본이 적거나 추세가 잡음 수준이면 내지 않습니다. 현장이라면 열화 모델을 맞추거나 베어링 결함 주파수 같은 주파수 분석을 함께 씁니다.

**공개 링크에 로그인 기능을 넣으면 위험하지 않나요?**
공개 링크로 온 쓰기 요청은 로그인보다 먼저 막습니다. 로그인 요청도 쓰기라서, 시연 계정 비밀번호가 알려져 있어도 공개 방문자는 로그인할 수 없습니다. 제어 키를 넣은 시연자 화면만 로그인할 수 있습니다. 로그인은 서명한 httpOnly 쿠키로 8시간 유지되고, 상태를 바꾼 요청은 감사 기록에 남습니다.

**OEE에서 정지 사유를 어떻게 다루나요?**
가동률 = (가동 + 투입 대기 + 배출 대기) / (경과 시간 − 계획 정지)입니다. 작업자가 고른 계획 정지와 `생산 계획 없음`은 분모에서 빠지고, 셋업과 고장은 가동률 손실로 남습니다. 투입·배출 대기는 성능 손실로 봤습니다.

**실제 공장이면 데이터는 어떻게 받나요?**
PLC → OPC UA → 엣지 게이트웨이 → MQTT 경로를 실제로 돌릴 수 있게 해 두었습니다(`npm run dev:opcua`). 인터록·작업지시 요청도 이 경로에서는 PLC 태그 핸드셰이크(요청 번호·응답 번호)로 주고받습니다. 토픽은 ISA-95 계층(사이트/라인/설비)을 따랐고, MES 쪽 코드는 그대로 둔 채 데이터 출처만 바꿀 수 있게 나눴습니다.

**AI가 틀린 답을 하면요?**
세 가지로 막았습니다. 숫자는 도구 조회 결과로만 말하게 했고, 답 위에 어떤 데이터를 조회했는지 보입니다. 원인 분석은 상관이라 "가능성이 높다"까지만 말하고 확인 방법을 줍니다. 그리고 비서에는 설비 조작 도구를 주지 않았습니다. 실제로 금형 온도 이상을 자재 LOT 문제로 잘못 답한 적이 있어, 설비 공정값과 자재 LOT를 가르는 규칙을 추가해 고쳤습니다.

**SPC 알람은 어떻게 내나요?**
X̄-R 관리도(부분군 5)에 Western Electric 규칙 일부(관리한계 이탈, 한쪽 9점 연속, 6점 연속 상승·하강)를 적용했습니다. 연속 태그는 자기상관이 있어 그래프만 그리고, 검사 측정값에만 알람을 냅니다. 오경보는 정상 운전에서 가상 1시간에 약 0.4건입니다.

**서버를 다시 띄우면 집계가 사라지나요?**
아닙니다. 실시간 집계와 실행 MES 상태(작업지시·NCR·Hold·격리 구역·초물 대기)는 메모리에서 쓰지만, 같은 내용을 DB에 모아 쓰므로 서버가 뜰 때 DB에서 되살립니다.

**배포는 어떻게 했나요?**
서버 비용 없이 이 노트북에서 운영 빌드를 띄우고 Cloudflare Tunnel로 HTTPS 링크를 만들었습니다. Vercel이나 Cloudflare Pages는 요청 때만 잠깐 도는 함수라, 늘 켜져 있어야 하는 시뮬레이터·MQTT 브로커·DB를 올릴 수 없었습니다. Claude 호출 비용이 새지 않게 IP별·하루 질문 한도도 걸었습니다. 늘 켜 둘 링크를 위해 Oracle Cloud 상시 무료 서버에 올리는 순서도 준비했습니다([`deploy/oracle/README.md`](../deploy/oracle/README.md)).

**더 하고 싶은 것은요?**
- 실제 공장처럼 사내 계정(SSO) 연동과 판정 때 다시 확인하는 전자 서명
- 남은 수명 추정을 열화 모델과 주파수 분석으로 바꾸기
- 작업표준서가 많아지면 임베딩을 더한 혼합 검색

## 문제가 생기면

| 증상 | 바로 할 것 |
|---|---|
| 상단 엣지 점이 빨강 (시뮬레이터 끊김) | 노트북: `npm run share`(또는 `npm run start`)를 다시 띄운다. 상시 서버: `pm2 restart lumitwin-sim`. 새 실행이 시작되니 시나리오는 다시 켠다 |
| 공개 링크가 안 나옴 (`429`, `context deadline exceeded`) | Cloudflare 빠른 터널 서비스가 잠시 막힌 것. 스크립트가 1~10분 간격으로 다시 시도한다. 기다리지 말고 노트북 화면과 같은 망 태블릿(`http://<노트북 IP>:5180/operator`, 마이크는 안 됨)으로 시연한다 |
| 공개 링크에서 버튼이 잠기고 `로그인`이 없음 | 보기 전용이다. `보기 전용`을 눌러 제어 키를 넣은 뒤 로그인한다 |
| 버튼이 흐리고 마우스를 올리면 "로그인이 필요합니다" | 로그인하지 않았다. 사용자 메뉴 자리의 `로그인`을 누른다 |
| "… 권한이 없습니다 (조장) · 품질·관리자만 할 수 있습니다" 같은 안내 | 역할이 다르다. 사용자 메뉴 → `다른 계정으로 로그인`에서 안내에 나온 역할로 바꾼다 |
| 계정 버튼을 눌러도 바로 안 들어감 (`아이디 채우기`) | 서버에 `DEMO_PASSWORD`를 정했다. 비밀번호를 넣고 `로그인`을 누른다 |
| "로그인 시도가 너무 많습니다. n초 뒤에 다시 해 주세요" | 1분에 10번 넘게 시도했다. 안내된 시간만큼 기다린다 |
| `/ncr`에 MRB 대기 건이 없음 | 웜기어 LOT를 늦게 켰다. 배속 `60×`에서 1분 30초쯤 기다리거나 다른 장면을 먼저 보여 준다 |
| 예지 보전에 경고가 아직 없음 | 베어링 마모 시나리오를 늦게 켰다. 경고까지 60배속 약 2~4분. 진동 추이가 오르는 것만 보여 주고 넘어가도 된다 |
| 게이트 설비가 `MES 확인 대기`로 오래 서 있음 | 초물 대기일 수 있다. `/changes`의 `초물 대기 설비`에서 확인한다. 품질 담당이면 `수동 합격`으로 풀 수 있다 |
| 시나리오 증상이 아직 약함 | 배속을 올리고 다른 화면을 먼저 보여 준 뒤 돌아온다 (위 표의 시간 참고) |
| AI 비서가 오류·한도 초과 | 서버의 키를 빼면 모의 모드로 같은 흐름을 보여 줄 수 있다. 시연 중에는 추천 질문 버튼을 누른다 |
| 마이크가 안 됨 | HTTPS가 아니거나 권한을 막은 것. 글로 입력한다 |
| 인터넷이 안 됨 | 노트북에서 `npm run start`로 로컬로만 띄운다 (5분 전에 미리 띄워 둘 것) |
