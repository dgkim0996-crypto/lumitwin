# LumiTwin 시연 대본

면접에서 화면을 띄워 놓고 보여 줄 때 쓰는 대본입니다. **5분 기본판**, **2분 짧은판**, **예상 질문**, **문제가 생겼을 때**로 나눴습니다.
"말할 것"은 그대로 읽어도 되게 썼고, "할 것"은 그때 누를 곳입니다.

> 가상 공장입니다. 공개 자료와 가정값으로 만들었고, SL의 실제 라인·수치·데이터를 쓰지 않았습니다. SL과 무관한 개인 프로젝트입니다.

## 준비 (시작 10분 전)

| 할 일 | 방법 |
|---|---|
| 노트북 화면 | 노트북에서 `npm run share`(운영 모드 + 공개 링크)를 띄우고 `http://localhost:5180`을 연다. 상단 오른쪽 MES·엣지 점이 초록색인지 본다. 공개 링크가 필요 없으면 `npm run start` |
| 태블릿·휴대폰 | 로그에 나온 공개 링크(`https://…trycloudflare.com`)의 `/operator`에서 **HL-VM-01 진공증착기**를 골라 둔다. 공개 링크는 보기 전용이므로 위쪽 `보기 전용`을 눌러 제어 키(`server/.env`의 `CONTROL_KEY`)를 넣어 `조작 가능`으로 바꾼다. 마이크 권한을 한 번 허락해 둔다 (HTTPS여야 묻는다) |
| 새 실행 | 데이터가 지저분하면 상단 `초기화`로 새 실행을 시작하고, 5배속으로 5분쯤 돌려 숫자를 쌓아 둔다 |
| AI 비서 모드 | 비서 창 위쪽에 `Claude` 또는 `모의 모드`가 보인다. 키가 없으면 모의 모드로 해도 시연 흐름은 같다 |
| 시나리오 | 시작 10분 전에 **웜기어 세트 불량 LOT 입고**와 **증착 챔버 미세 누설**을 켜고 `20×`로 5분 돌린 뒤 `5×`로 내린다. 그러면 시연을 시작할 때 증상이 이미 쌓여 있다 |
| 창 배치 | 노트북은 3D 공장, 태블릿은 작업자 화면. 화면 공유면 브라우저 탭 두 개(3D 공장, `/operator/HL-VM-01`) |

**시나리오가 증상을 내기까지 걸리는 시간** (시뮬레이터로 잰 값. 실제 시간 = 가상 시간 ÷ 배속)

| 시나리오 | 잰 결과 | 가상 시간 | 20배속 | 60배속 |
|---|---|---|---|---|
| 웜기어 세트 불량 LOT 입고 | 켜고 1.5시간 뒤 사이드미러 기능 검사 불량률 23.6% (소음 25건·모터 전류 4건) | 1.5시간 | 4분 30초 | 1분 30초 |
| 증착 챔버 미세 누설 | 켜고 약 50분 뒤 펌프다운 시간이 관리 상한(14분)을 넘고, 그 무렵 백화 불량률 상승 알람이 뜸 | 약 50분 | 약 2분 30초 | 약 50초 |

시나리오는 끌 때까지 효과가 남는다(누설은 상한까지 커진 채로 유지). 시연이 끝나면 꺼 둔다.

## 예상 질문

**왜 가상 데이터인가요?**
실제 공장 데이터는 대외비라 쓸 수 없습니다. 대신 공정 순서·파라미터를 공개 자료로 조사하고, 근거 등급(확인·약함·가정)을 모든 값에 달았습니다. 불량 인과도 "원인 공정과 증상 공정이 다르다"는 현장 특성을 넣어, 데이터를 따라가야 원인이 보이게 만들었습니다.

**OEE에서 정지 사유를 어떻게 다루나요?**
가동률 = (가동 + 투입 대기 + 배출 대기) / (경과 시간 − 계획 정지)입니다. 작업자가 고른 계획 정지는 분모에서 빠지고, 셋업과 고장은 가동률 손실로 남습니다. 투입·배출 대기는 성능 손실로 봤습니다. 사유는 설비 상태 이력에 남아, 손실을 종류별로 나눠 볼 수 있습니다.

**실제 공장이면 데이터는 어떻게 받나요?**
PLC → OPC UA → 엣지 게이트웨이 → MQTT(Sparkplug B) 경로를 생각했습니다. 토픽은 ISA-95 계층(사이트/라인/설비)을 따랐고, 시뮬레이터가 그 엣지 자리에 있습니다. MES 쪽 코드는 그대로 둔 채 데이터 출처만 바꿀 수 있게 나눴습니다.

**AI가 틀린 답을 하면요?**
세 가지로 막았습니다. 숫자는 도구 조회 결과로만 말하게 했고, 답 위에 어떤 데이터를 조회했는지 보입니다. 원인 분석은 상관이라 "가능성이 높다"까지만 말하고 확인 방법을 줍니다. 그리고 비서에는 설비 조작 도구를 주지 않았습니다. 실제로 금형 온도 이상을 자재 LOT 문제로 잘못 답한 적이 있어, 설비 공정값과 자재 LOT를 가르는 규칙을 추가해 고쳤습니다.

**SPC 알람은 어떻게 내나요?**
X̄-R 관리도(부분군 5)에 Western Electric 규칙 일부(관리한계 이탈, 한쪽 9점 연속, 6점 연속 상승·하강)를 적용했습니다. 연속 태그는 자기상관이 있어 그래프만 그리고, 검사 측정값에만 알람을 냅니다. 오경보는 정상 운전에서 가상 1시간에 약 0.4건입니다.

**작업자 화면에서 신경 쓴 점은요?**
장갑 낀 손을 생각해 누르는 곳을 크게(최소 48px, 주요 버튼 80px) 했고, 재가동·수리 완료처럼 위험한 동작은 안전 확인 체크를 해야 누를 수 있게 했습니다. 작업 전 점검 항목은 작업표준서에서 읽어 와서, 표준서를 고치면 화면도 따라 바뀝니다. 손을 쓰기 어려울 때를 위해 음성 질문 버튼을 크게 두었습니다.

**서버를 다시 띄우면 집계가 사라지나요?**
아닙니다. 실시간 집계는 메모리에서 계산하지만, 같은 이벤트를 DB에 1초마다 모아 쓰므로 서버가 뜰 때 DB에서 0.5초 안에 되살립니다.

**배포는 어떻게 했나요? 보안은요?**
서버 비용 없이 이 노트북에서 운영 빌드를 띄우고 Cloudflare Tunnel로 HTTPS 링크를 만들었습니다. Vercel이나 Cloudflare Pages는 요청 때만 잠깐 도는 함수라, 늘 켜져 있어야 하는 시뮬레이터·MQTT 브로커·DB를 올릴 수 없었습니다. 공개 링크로 들어온 요청은 Cloudflare가 붙이는 머리글로 가려 서버가 쓰기 요청을 막고(보기 전용), 시연자만 제어 키로 풉니다. Claude 호출 비용이 새지 않게 IP별·하루 질문 한도도 걸었습니다. 늘 켜 둘 링크가 필요하면 서버 한 대에 Caddy·pm2로 올리는 스크립트도 준비해 두었습니다. 자세한 것은 [`deploy/cloudflare/README.md`](../deploy/cloudflare/README.md)에 있습니다.

**더 하고 싶은 것은요?**
- OPC UA 시뮬레이터를 하나 붙여 실제 프로토콜 경로를 보이는 것
- 비가동 사유를 6대 로스로 묶어 보여 주는 손실 분석 화면
- 작업표준서가 많아지면 임베딩을 더한 혼합 검색

## 문제가 생기면

| 증상 | 바로 할 것 |
|---|---|
| 상단 엣지 점이 빨강 (시뮬레이터 끊김) | 노트북: `npm run share`(또는 `npm run start`)를 다시 띄운다. 상시 서버: `pm2 restart lumitwin-sim`. 새 실행이 시작되니 시나리오는 다시 켠다 |
| 공개 링크가 안 나옴 (`429`, `context deadline exceeded`) | Cloudflare 빠른 터널 서비스가 잠시 막힌 것. 스크립트가 1~10분 간격으로 다시 시도한다. 기다리지 말고 노트북 화면과 같은 망 태블릿(`http://<노트북 IP>:5180/operator`, 마이크는 안 됨)으로 시연한다 |
| 공개 링크에서 버튼이 잠김 | 보기 전용이다. `보기 전용`을 눌러 제어 키를 넣는다 |
| 시나리오 증상이 아직 약함 | 배속을 20×로 올리고 다른 화면을 먼저 보여 준 뒤 돌아온다 (위 표의 시간 참고) |
| AI 비서가 오류·한도 초과 | 서버의 키를 빼면 모의 모드로 같은 흐름을 보여 줄 수 있다. 시연 중에는 추천 질문 버튼을 누른다 |
| 마이크가 안 됨 | HTTPS가 아니거나 권한을 막은 것. 글로 입력한다 |
| 인터넷이 안 됨 | 노트북에서 `npm run start`로 로컬로만 띄운다 (5분 전에 미리 띄워 둘 것) |
